## 1. システム構成

```
ブラウザ (public/: index.html, app.js, style.css — SPA, ハッシュルーティング)
   │  HTTPS/HTTP (JSON API, Cookie セッション)
server.js (node:http)  … ルーティング / 認証 / CSRF チェック / 静的ファイル配信
   ├ lib/workflow.js   … 稟議ワークフロー (状態遷移・権限・監査ログ・ユーザー/テンプレート管理)
   ├ lib/auth.js       … パスワードハッシュ (scrypt)・セッション・ログイン試行制限
   ├ lib/backup.js     … バックアップ (CSV・添付書き出し・DB コピー)
   └ lib/db.js         … スキーマ・マイグレーション・初期データ
data/ringi.db (SQLite, WAL) / backups/ (バックアップ出力)
```

## 3. 業務仕様

### 3-1. 稟議の状態遷移

```
draft(下書き) ──申請──▶ pending(承認中) ──全ステップ承認──▶ approved(承認済)
   ▲                       │   │   │
   │                       │   │   └─却下────────▶ rejected(却下)      ※終了
   │                       │   └─取下げ(申請者)──▶ withdrawn(取下げ)   ※終了
   │                       ├─差戻し(申請者へ)──▶ returned(差戻し中) ──再申請──▶ pending（ステップ1から・round+1）
   │                       └─差戻し(前ステップへ)──▶ pending（current_seq を戻す。戻した区間の判断はクリア）
   └── 下書き保存 / 編集（draft・returned のみ）
```

### 3-2. 承認ステップ
- 稟議ごとにステップ列（`ringi_steps`）を保持（テンプレートのスナップショット、または個別指定）。テンプレートの後からの変更は既存稟議に影響しない
- ステップの承認方式: `any`（誰か 1 人が承認で通過）/ `all`（全員承認で通過）
- テンプレートのステップは `min_amount`（適用最低金額）を持ち、申請金額が未満なら申請時に除外される
- 承認者は**承認者権限**（`users.is_approver = 1`）かつ有効なユーザーのみ指定可能
- 現在のステップ（`current_seq`）の承認者で未判断の者だけが 承認 / 却下 / 差戻し を実行できる
- 却下・差戻しはコメント必須。差戻し先は「申請者（0）」または「承認済みの前ステップ」

### 3-3. 権限
| 操作 | 可能なユーザー |
|---|---|
| 閲覧 | 申請者、ルート上の承認者、管理者 |
| 作成・編集・申請・再申請・取下げ・下書き削除 | 申請者本人（編集・申請は draft / returned のみ、取下げは pending のみ、削除は draft のみ） |
| 承認 / 却下 / 差戻し | 現在ステップの承認者（未判断） |
| コメント | 閲覧できるユーザー |
| テンプレート編集、ユーザー管理、バックアップ | 管理者（`role = 'admin'`） |

### 3-4. 監査ログ
`history` に 作成 / 編集 / 申請 / 再申請 / 承認 / 却下 / 差戻し（差戻し先） / 取下げ / コメント を、操作者・日時・ステップ・申請回（round）・コメント付きで記録。詳細画面のタイムラインに表示。

### 3-5. 制限値
| 項目 | 値 |
|---|---|
| 添付ファイル | 1 件 5MB、1 稟議 5 件 |
| 明細 | 50 行 |
| 承認ステップ | 20 ステップ |
| 件名 200 文字、内容 20,000 文字、コメント 2,000 文字 | |
| パスワード | 8 文字以上 128 文字以下 |
| ログインID | 3〜50 文字の半角英数字と `. _ @ -`、一意 |
| セッション | 7 日 |
| ログイン失敗 | 連続 5 回で 60 秒ロック |

## 4. 認証・セキュリティ

- パスワード: scrypt（salt 16byte、64byte 出力）でハッシュ化。API レスポンスにハッシュは含めない
- セッション: ランダム 32byte トークン。DB にはトークンの SHA-256 を保存。Cookie `sid`（HttpOnly, SameSite=Lax, 7 日, `RINGI_SECURE_COOKIE=1` で Secure）
- CSRF: GET 以外の API は `X-Requested-With: fetch` ヘッダ必須（SameSite Cookie と併用）
- 無効化 / パスワード再設定 / 管理者権限解除 時は対象ユーザーの全セッションを破棄。本人のパスワード変更時は他セッションを破棄
- ログイン失敗の試行制限（ログインID 単位、プロセス内メモリ）
- 入力値はサーバー側で検証（長さ・型・権限・状態）。HTML 出力はすべてエスケープ
- 静的ファイル配信はパストラバーサルを拒否
- 本番は HTTPS（リバースプロキシ）配下での運用を前提

## 5. データベース定義（SQLite）

| テーブル | 主なカラム | 内容 |
|---|---|---|
| `users` | id, login_id(一意), password_hash, name, dept, title, role('user'/'admin'), is_approver, active | ユーザー |
| `sessions` | id(トークンのSHA-256), user_id, created_at, expires_at, last_seen_at, user_agent | ログインセッション |
| `route_templates` | id, name, description, created_at | 承認ルートテンプレート |
| `route_template_steps` | id, template_id, seq, name, mode('any'/'all'), min_amount | テンプレートのステップ |
| `route_template_step_approvers` | step_id, user_id | テンプレートステップの承認者 |
| `ringi` | id, number('R-YYYY-NNNN' 一意), title, category, amount, body, desired_date, vendor, items_json, applicant_id, template_id, status, current_seq, round, created_at, updated_at, submitted_at, completed_at | 稟議 |
| `ringi_steps` | id, ringi_id, seq, name, mode, status('waiting'/'active'/'approved'/'returned'/'rejected'), activated_at, completed_at | 稟議ごとの承認ステップ |
| `ringi_step_approvers` | id, step_id, user_id, decision(NULL/'approved'/'rejected'/'returned'), decided_at, comment | ステップごとの承認者と判断 |
| `history` | id, ringi_id, actor_id, action, from_status, to_status, step_seq, step_name, target_seq, round, comment, created_at | 監査ログ |
| `attachments` | id, ringi_id, filename, mime, size, data(BLOB), uploaded_by, created_at | 添付ファイル |

- 外部キー制約有効（`PRAGMA foreign_keys = ON`）、稟議削除時は関連行をカスケード削除
- ジャーナル: WAL
- スキーマ変更は起動時の自動マイグレーション（カラム追加）で適用

## 6. API 一覧（JSON）

認証: Cookie `sid`。GET 以外は `X-Requested-With: fetch` 必須。エラーは `{ "error": "メッセージ" }`（400 入力エラー / 401 未ログイン / 403 権限なし / 404 / 429 ロック中）。

| Method | Path | 内容 |
|---|---|---|
| POST | /api/auth/login | ログイン `{login_id, password}` |
| POST | /api/auth/logout | ログアウト |
| POST | /api/auth/password | パスワード変更 `{current_password, new_password}` |
| GET | /api/me | ログインユーザー |
| GET | /api/users | 有効ユーザー一覧（承認者選択用） |
| GET | /api/users?all=1 | 全ユーザー（管理者） |
| POST / PUT | /api/users, /api/users/:id | ユーザー作成 / 更新（管理者） |
| GET | /api/constants | ステータス等のラベル定義 |
| GET / POST | /api/templates | テンプレート一覧 / 作成（管理者） |
| GET / PUT / DELETE | /api/templates/:id | 取得 / 更新 / 削除（管理者） |
| GET | /api/templates/:id/resolve?amount=N | 金額条件適用後のステップ列 |
| GET | /api/ringi?filter=inbox\|mine\|all&status=&q= | 一覧 |
| GET | /api/ringi/counts | バッジ用件数 |
| POST | /api/ringi | 作成（`submit: true` で同時に申請） |
| GET / PUT / DELETE | /api/ringi/:id | 詳細 / 編集 / 下書き削除 |
| POST | /api/ringi/:id/submit · approve · reject · return · withdraw · comment | 申請 / 承認 / 却下 / 差戻し `{target_seq, comment}` / 取下げ / コメント |
| GET | /api/ringi/:id/attachments/:aid | 添付ダウンロード |
| GET / POST | /api/admin/backups | バックアップ一覧 / 作成（管理者） |
| DELETE | /api/admin/backups/:name | バックアップ削除（管理者） |
| GET | /api/admin/export/:table.csv | テーブル単位 CSV（管理者） |

詳細レスポンスの `perms` に、そのユーザーが実行できる操作（`can_approve`, `can_return`, `return_targets` など）が含まれます。

## 7. バックアップ仕様

`backups/backup_YYYYMMDD_HHMMSS/` に以下を出力（詳細は導入手順書 5 章）。

- CSV（UTF-8 BOM 付き・CRLF・日本語ヘッダ）: users / route_templates / route_template_steps / ringi / ringi_items / ringi_steps / ringi_step_approvers / history / attachments
- `attachments/` 添付ファイル実体（`<稟議番号>_<添付ID>_<元ファイル名>`）
- `ringi.db` SQLite 完全コピー（`VACUUM INTO`）
- `manifest.json` / `README.txt`

## 9. 既知の制約・今後の拡張候補

- 添付ファイルは DB 内（BLOB）に保存。大量・大容量運用時は外部ストレージへの変更を推奨
- メール通知、代理承認、稟議の PDF 出力、SSO 連携は未実装（要望に応じて拡張可能）
- ログイン試行制限はプロセス内メモリのため、再起動でリセットされる
